# SEO Content Roadmap (GrowthOS)

Goal: maximize topical authority + entity clarity for `GrowthOS` on `https://grothos.in/`, without creating thin/doorway pages.

## P0 (implement first / already implemented)
1. `/` (Homepage) — primary brand + product loop
2. `/seo-aeo-geo` — pillar explaining SEO vs AEO vs GEO + approve → verify → rollback
3. `/ai-visibility` — pillar for AI visibility / GEO with safe implementation workflow
4. `/compare` — comparison between GrowthOS and research-first tools
5. `/pricing` — transactional page with clear limits and verification/rollback positioning

## P1 (high priority, planned)
1. `/ai-seo` — AI-powered SEO (definition + GrowthOS scan/propose/approve/deploy/verify workflow)
2. `/seo-automation` — SEO automation vs reporting vs research; position GrowthOS as implementation layer
3. `/technical-seo` — technical SEO issue categories GrowthOS can scan + safe fix classes (titles, canonicals, FAQ schema, robots/sitemap, etc.)
4. `/wordpress-seo` — explicit WordPress workflow (Connect → Scan → Propose → Approve → Backup → Deploy → Verify → Rollback)
5. `/seo-agencies` — agency workflow (audit trails, client approvals, safe deployments, verification/rollback)

## P2 (supporting use-cases, planned)
1. `/faq-schema` — add/fix FAQ schema safely (problem → who needs it → how GrowthOS does it → verify → rollback)
2. `/canonical-seo` — canonical URL optimization safely
3. `/seo-audit` — what a GrowthOS “scan” finds vs what it executes
4. `/seo-implementation` — how proposals get deployed safely
5. `/seo-verification` — how verification works post-deploy
6. `/seo-rollback` — rollback behavior when verification fails

## Internal linking approach (applies to all new pages)
- Homepage → each pillar page (AI visibility, SEO/AEO/GEO, AI SEO, Technical SEO, etc.)
- Pillars cross-link to relevant use-cases (FAQ schema, canonicals, verification, rollback)
- Avoid exact-match anchor repetition; use descriptive anchors (e.g., “safe canonical fixes”, “FAQ schema proposals”, “AI visibility workflow”)

## Schema approach (applies to all new pages)
- Keep JSON-LD truthful and machine-oriented (Organization, SoftwareApplication, WebPage, and page-specific FAQPage when visible)
- No fake reviews/ratings, no invented company facts
